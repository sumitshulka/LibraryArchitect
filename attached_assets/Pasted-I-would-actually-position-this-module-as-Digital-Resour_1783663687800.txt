I would actually position this module as **Digital Resources**, not **Digital Resource Catalog**.

The word *Catalog* implies metadata only. What you're building is an institutional repository where users can actually consume the content.

Below is a prompt designed for **Replit AI** that follows the same enterprise architecture as the rest of Scholars24.

---

# Replit Prompt – Build Digital Resources Module (Phase I)

## Project Overview

Build an enterprise-grade **Digital Resources Module** for the Scholars24 Library Management System (LibraTech).

This module is **NOT** a Learning Management System and **NOT** a DRM platform.

Its purpose is to provide institutions with a centralized repository where digital learning resources can be uploaded, organized, searched, managed and securely accessed by authorized users.

The system should follow the same UI/UX style as the existing LibraTech modules.

---

# Module Name

Digital Resources

Appears in the left navigation below Catalog.

---

# Objectives

Allow institutions to

* Upload digital assets
* Organize resources
* Categorize by academic hierarchy
* Control who can access resources
* Maintain versions
* Search quickly
* Track usage

There is NO DRM in Phase I.

Students can download resources if permission allows.

# Design Philosophy

The module should feel like an enterprise **Digital Knowledge Repository** rather than a simple file manager. The interface should emphasize discoverability, structured academic organization, and ease of access, while maintaining consistency with the existing LibraTech design language. Future AI, analytics, and research capabilities should be easy to plug into this foundation without requiring major architectural changes.

This prompt gives Replit enough functional and architectural detail to generate a production-grade Phase I module that aligns naturally with the rest of the Scholars24 ecosystem.
